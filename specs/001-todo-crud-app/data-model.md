# データモデル: TODOアプリケーション

**作成日**: 2025-10-22
**機能**: [spec.md](spec.md)

## エンティティ定義

### Task（タスク）

タスク管理システムの中核エンティティ。ユーザーが作成・編集・削除するすべてのタスクを表す。

#### フィールド

| フィールド名 | 型 | 必須 | デフォルト | 説明 |
|------------|-----|------|----------|------|
| `id` | UUID/String | ✅ | 自動生成 | 一意のタスク識別子。保存時に自動割り当て |
| `title` | String | ✅ | - | タスク名。1～100文字 |
| `description` | String | ❌ | "" | タスク説明。0～500文字 |
| `completed` | Boolean | ✅ | false | 完了フラグ。true=完了、false=未完了 |
| `createdAt` | ISO 8601 DateTime | ✅ | 現在時刻 | 作成日時。UTC形式 |
| `updatedAt` | ISO 8601 DateTime | ✅ | 現在時刻 | 最後の更新日時。UTC形式 |

#### バリデーションルール

```javascript
title:
  - 必須（空文字列不可）
  - 最小1文字、最大100文字
  - 前後の空白を自動削除
  - 特殊文字は許可（ユーザーの入力をそのまま保持）

description:
  - オプション（省略可）
  - 最大500文字
  - 前後の空白を自動削除
  - 改行・特殊文字を許可

completed:
  - ブール値のみ受け入れ
  - デフォルト: false

createdAt / updatedAt:
  - ISO 8601 形式（例: 2025-10-22T10:30:00Z）
  - システムで自動管理（ユーザー入力不可）
```

#### 状態遷移

```
[新規] → [未完了] ← → [完了] → [削除]
```

- 新規作成時は常に `completed: false` で開始
- `completed` の値は任意のタイミングでトグル可能
- 削除操作で完全に削除される（論理削除ではなく物理削除）

#### 例

```json
{
  "id": "task-12345",
  "title": "買い物リストを作成する",
  "description": "月曜日のスーパーでの買い物に必要な品目をまとめておく",
  "completed": false,
  "createdAt": "2025-10-22T09:15:00Z",
  "updatedAt": "2025-10-22T09:15:00Z"
}
```

## ローカルストレージスキーマ

**保存先**: ブラウザ LocalStorage（キー: `"tasks"`）

```javascript
localStorage.setItem('tasks', JSON.stringify([
  {
    id: "1729580100000",  // Date.now() で生成
    title: "買い物に行く",
    description: "スーパーで牛乳とパンを買う",
    completed: false,
    createdAt: "2025-10-22T09:00:00Z",
    updatedAt: "2025-10-22T09:00:00Z"
  },
  // ... その他のタスク
]));
```

**容量**: 5～10MB per domain
**容量内でサポート**: 10,000+ タスク

## リレーション

現在のスコープでは、Task エンティティ単独で実装。ユーザー、グループ、プロジェクトなどのリレーションは含めない（MVP）。

## データフロー

### タスク作成フロー

```
1. UI で title + description を入力
2. バリデーション実行
3. id を自動生成（UUID）
4. createdAt / updatedAt を現在時刻で設定
5. completed を false でセット
6. ストレージに追加
7. UI に新規タスクを反映
```

### タスク更新フロー

```
1. 既存タスクを ID で取得
2. title / description / completed を変更
3. updatedAt を現在時刻で更新
4. createdAt は保持（変更しない）
5. ストレージに上書き
6. UI に変更を反映
```

### タスク削除フロー

```
1. 削除対象タスクを ID で取得
2. ストレージから削除（物理削除）
3. UI から削除
```

## パフォーマンス・制約

| 要件 | 目標 | 備考 |
|------|------|------|
| タスク保存速度 | < 100ms | LocalStorage 書き込み（同期） |
| タスク読み込み速度（100タスク） | < 50ms | LocalStorage 読み込み |
| メモリ使用量（100タスク） | < 50KB | JSON データ構造 |
| 最大タスク数 | 10,000+ | ブラウザ LocalStorage 容量次第 |
